# Защита секретов — 0.5.5

## Реализовано

- В интерфейсе показываются только найденные предметы, без общего количества, индекса,
  технического ID, незаполненных ячеек или процентов коллекции.
- Публичное название и описание активного предмета хранятся вместе с его определением
  в шифрованном resources/private/content.dat. Семантический ID заменён непрозрачным токеном.
- Будущие определения достижений хранятся в отдельном шифрованном milestones.dat.
- В контейнерах: AES-256-CBC, PKCS7, случайный IV, HMAC-SHA256 с отдельным ключом;
  MAC проверяется до расшифрования, включая назначение контейнера, заголовок и IV.
- Профиль v5 шифрует коллекцию в поле vault. Настройки, обычный прогресс и рекорды остаются JSON.
- v1–v4 читаются совместимо. Старый идентификатор принимается только для миграции.
  Перед созданием резервной копии открытая коллекция v4 преобразуется в шифрованную.
  После восстановления повреждённый основной файл не заменяет хорошую резервную копию.
- Если активное определение недоступно, награды не выдаются; существующая коллекция
  защищена от перезаписи. Ошибка подписи контейнера не превращается в открытие.
- Player export исключает resources/arcade/secrets.json, открытый реестр достижений,
  старый именованный Resource, tools, tests и docs. Установочный ZIP содержит только игру,
  инструкцию без спойлеров и лицензии. Архив исходников — отдельный материал для разработчика.

## Чего это не гарантирует

Клиентские ключи намеренно находятся в коде офлайн-игры. Они не являются серверными
секретами и могут быть извлечены из программы/памяти, особенно при наличии исходников.
Локальные HMAC/шифрование защищают от обычного чтения и случайного изменения, а не
доказывают честность игрока, не защищают мировой рейтинг и не определяют первооткрывателя.
Весь PCK/код не объявляется зашифрованным: применены стандартные Godot export templates.
Публичная история репозитория и старые архивы не становятся секретными задним числом.

Для строгого сокрытия неоткрытых данных нужен сервер, не передающий их клиенту.
Он же должен проверять авторизацию, попытки и условия, атомарно назначать первенство.
Сервис и Steamworks пока не подключены; UI сообщает об этом. Старый артефакт Приключения
не становится официальной находкой Аркады и не присваивает мировой статус.

## Сборка и проверки

При изменении разработческих определений:
`godot --headless --path . --script tools/build_private_data.gd`.
Генерация использует новый IV; ciphertext закономерно отличается при том же содержимом.
Исходные JSON под tools/resources остаются только в developer archive/GitHub.

`tools/verify.py` запускает импорт, parser preflight, поведенческие тесты и основную сцену.
`tools/privacy_export_smoke.gd` запускается внешним QA-скриптом фактического Linux-экспорта
из пустой папки вне дерева исходников: иначе res:// может читать локальные файлы и
ошибочно показывать исключённые из PCK данные. Логи: docs/qa/exported_privacy.txt.
Независимая проверка Python cryptography подтверждает расшифрование и MAC двух контейнеров.

Native Windows, изображение/звук и физические контроллеры проверяются отдельно.
