# Дополнительное сокрытие секретов 0.6.0

Вместо увеличения числа отдельных «секретных» файлов сокращён объём сведений в клиенте.

- Все неработающие и скрытые определения достижений исключены из release payload.
  Полный реестр предметов уже исключён в 0.5.5. Будущие предметы/условия не отправляются.
- Один нейтрально названный шифрованный runtime.bin содержит активные условия и публичные
  рабочие достижения. Отдельных файлов на каждый скрытый предмет нет.
- Внутри контейнера случайное заполнение до блока 16 КиБ. Изменение небольшого текста/набора
  полей не приводит к изменению размера файла на соответствующее число байт.
- Название/описание активного предмета остаются отдельным шифротекстом даже после загрузки
  условий; расшифровываются при отображении. Постоянного кэша открытого текста в определении нет.
- Семантические названия предмета убраны из runtime-имён класса значка/констант/методов;
  специфические пороги условия больше не зашиты в загрузчике как литералы.
- UI продолжает показывать только собственные найденные публичные данные, без ID, общих
  чисел, неизвестных названий, процентов или пустых мест скрытой коллекции.

AES/HMAC, случайный IV и совместимость коллекции 0.5.5 сохранены. Эти меры затрудняют
поиск текстом, просмотр структуры/размеров и случайное извлечение метаданных. Это не DRM:
исполняемый офлайн-клиент и его ключи доступны владельцу, а публичный репозиторий/исходники
содержат разработческие материалы. Весь PCK/код не зашифрован.

Для строгой тайны недоставленные условия/подтверждения мировых открытий должны оставаться
на сервере. Одиночная игра работает офлайн; мировой статус потребует проверенной сервером
попытки и атомарного назначения первого игрока. Сервис пока не подключён.

Сборка: tools/build_private_data.gd. Фактическое отсутствие лишних данных проверяется
privacy_export_smoke.gd из пустой папки вне исходников. Независимый Python crypto interop
проверяет наружный контейнер и вложенные данные отображения, а также фильтрацию определений.
