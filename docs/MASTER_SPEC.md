Актуальная основа проекта: требования 2.0–2.5, уточнения меню/Кампании и полное дополнение 2.4. Последние правила Кампании 2.5 сохраняются.
Полные отдельные тексты 2.1/2.2 не получены; отсутствующие положения не домысливаются.
Статусы реализации находятся в ROADMAP.md и QA_REPORT.md, а не следуют из наличия требования.

## Новое решение владельца 16.10.2026 — три режима и международный интерфейс

Этот раздел имеет приоритет над прежним меню и разделением Кампании/Классики ниже.

- Основных режимов ровно три: **Аркада, Арена, Приключение**.
- Кампания/Классика не являются дополнительными пунктами. Их сохранённое путешествие и правила переходят внутрь Приключения; старый прогресс сохраняется.
- Мастерская — отдельный редактор: один/два игрока, прохождение/арена, настраиваемая сложность. Предусмотрены соло, кооператив, локальная дуэль и соло против ботов.
- Официальные пасхалки предусмотрены в каждом из трёх основных режимов. В Мастерской нет инструментов, подсказок, списка, условий или каталога пасхалок; импорт пользовательских данных не может выдавать официальные находки.
- Релизная граница остаётся 51 уровнем; ещё 49 добавляются позже.
- Добавляются текстовые языки: японский, корейский, упрощённый китайский, хинди, индонезийский, тайский, вьетнамский, французский, итальянский, немецкий, арабский, турецкий. Русский/английский сохраняются.
- Язык выбирается удобным списком с родными и локализованными названиями/поиском; выбор сохраняется. Все игровые экраны, настройки, редактор, бонусы, достижения и уже найденные предметы используют актуальный язык. Пользовательский текст карт не переводится автоматически.
- Нужны встроенные шрифты, проверка подстановок/переносов, корректная арабская письменность и RTL интерфейс без зеркалирования поля/управления. Техническая полнота не заменяет вычитку носителями.
- Меню: три заметные карточки режима, отдельные Мастерская/коллекция/помощь/настройки/язык/выход; ясный фокус для клавиатуры и контроллера.
- Оформление сохраняет 2.5D: оригинальный маленький шахтёр, разные фантастические враги, предметные бонусы, читаемые свет/тени/опасности.
- Перед Steam нужны исследование аналогов, сравнение пользовательской ценности, предложение цены и проверяемый список работ. Цены не устанавливаются во внешней системе автоматически.

Статус реализации 0.7.4: три режима, четыре формата редактора, 14 языков, процедурное оформление и действующие локальные находки; Аркада содержит 20 авторских этапов в двух главах, включая «Затопленные руины» с непроходимой водой и мостами. Выбор этапов и рекорды разделены по главам. Добавлены справочник, подсказки способностей и разбор результата; в 0.7.3 — деления фитиля, отдельный вид дистанционных бомб, ограниченные эффекты событий и приоритеты звуков. Точные проверки и ограничения — QA_REPORT.md. Это не готовая Steam 1.0 и не подтверждение готовности всех 51 авторских уровней.

## Защита данных секретов — дополнение владельца 15.10.2026

1. Не показывать технические ID, индексы, внутренние номера, порядковые метки секретов
   в таблицах, уведомлениях, описаниях, именах файлов, экспортируемых пользовательских картах или обычных логах.
2. Внутри приложения использовать случайные непрозрачные идентификаторы без названия предмета
   и без последовательной нумерации. На экран передавать только разрешённую публичную модель находки.
3. Полный разработческий реестр, будущие артефакты, условия, карты размещения, тестовые
   находки и документы со спойлерами исключать из устанавливаемой сборки. Архив исходников
   является отдельным разработческим материалом и не должен поставляться игрокам вместе с игрой.
4. Необходимые клиенту определения активных секретов и локальные записи находок хранить
   в зашифрованных контейнерах с проверкой целостности и случайным IV. Повреждённые данные
   не должны превращаться в награды; старые сохранения мигрировать с сохранением прогресса.
5. Клиентское шифрование — защита от обычного просмотра файлов. Ключ и исполняемые условия,
   доступные офлайн-клиенту, могут быть извлечены при анализе программы или памяти.
   Не обещать невозможность узнать количество/условия реверс-инжинирингом.
6. Для строгого сокрытия не отправлять клиенту данные неоткрытых секретов. Авторитетный
   реестр, серверные ключи, проверку заявок и глобальное первенство хранить на сервере.
   До запуска сервиса честно показывать его недоступность; тестовые победители только в тестах.
7. Проверять релизный пакет автоматически: отсутствие открытого полного реестра, исходных
   условий, внутренних ID и счётчиков в UI/инструкциях; наличие и читаемость шифрованных
   активных данных; невозможность получить награду при ошибке чтения/проверки целостности.
8. Шифрование PCK целиком — отдельный этап с собственными export templates. Использование
   стандартных шаблонов Godot само по себе не означает, что PCK или весь код зашифрованы.
9. Публичная история GitHub и уже выпущенные старые архивы не становятся секретными
   после обновления. Не менять видимость репозитория и не переписывать историю без отдельного указания владельца.


Последнее правило меню: «Классика» входит в «Кампанию», согласно обновлению 2.5.

1. Кампания: уничтожить обязательных врагов, раскрыть скрытый выход, войти в него.

5. Стрелки — основное управление; переназначения пользователя сохраняются. Геймпады, Steam Deck/SteamOS/Steam Machine — целевые устройства, консоли — будущие порты. Наличие цели не означает проверку на устройстве.
6. Исторический прототип arcade_v1 и его рекорды не являются официальной Аркадой 2.3. Они сохраняются отдельно для совместимости.
7. Большие многоэкранные карты, 2.5D, общая механика бомб, оригинальная интеллектуальная собственность и требования качества сохраняются.
8. При чтении унаследованных разделов упоминания выхода/классического прохождения относятся к кампании. Процедурная геометрия относится к пользовательским картам. Требования 2.3 ниже определяют официальную Аркаду и Мастерскую полностью.

- Большие многоэкранные лабиринты.
- Свободное исследование уровней.

# ЧАСТЬ II. КЛАССИЧЕСКИЕ ПРАВИЛА — НЕИЗМЕННОЕ ЯДРО

## 3. Классический Bomberman как механическая основа

Изучи доступные исторические материалы по Bomberman для NES/Famicom, оригинальные руководства и описания игровых механик.

Зафиксируй правила в отдельном документе CLASSIC_RULES.md.

Классическая кампания использует нижеперечисленные принципы. Они не задают условие победы Аркады или мультиплеера.

Отделяй подтверждённые исторические правила от новых решений BLASTORIA.

### 3.1. Основная цель

Каждый уровень — лабиринт с неразрушимыми стенами, разрушаемыми блоками, противниками, скрытыми усилениями и спрятанным выходом.

Чтобы пройти уровень, игрок должен:

1. Исследовать лабиринт.
2. Устанавливать бомбы.
3. Разрушать препятствия.
4. Уничтожить всех обязательных врагов.
5. Найти скрытый выход.
6. Встать на клетку выхода.
7. Перейти на следующий уровень.

Простого нахождения выхода недостаточно.

До выполнения условий победы выход остаётся закрытым.

### 3.2. Стартовые возможности персонажа

В исторически точном пресете классического режима:

- Одна одновременно активная бомба.
- Дальность взрыва — одна клетка в каждом направлении.
- Бомба взрывается автоматически по таймеру.
- Игрок получает поражение при попадании в обычный взрыв.
- Игрок получает поражение при столкновении с опасным врагом.
- Улучшения находятся внутри разрушаемых блоков.

Точное время детонации, длительность взрыва и скорость движения вынести в конфигурацию.

Параметры для современной кампании могут отличаться, но не должны незаметно подменять пресет «Классика».

### 3.3. Распространение взрыва

Взрыв распространяется в четыре стороны:

- Вверх.
- Вниз.
- Влево.
- Вправо.

Не используется диагональный взрыв по умолчанию.

Правила:

- Прочная стена полностью останавливает луч.
- Разрушаемый блок уничтожается и останавливает луч.
- Открытый коридор пропускает взрыв.
- Противник в зоне поражения погибает.
- Игрок в зоне поражения погибает при отсутствии защитной способности.
- Другая бомба может взорваться досрочно.
- Взрывы могут формировать цепные реакции.

Одновременные события разрешать детерминированно.

### 3.4. Неразрушимые стены

Служат:
- Укрытиями.
- Границами маршрутов.
- Основой головоломок.
- Ограничителями распространения взрывов.

Классический режим не должен позволять уничтожать их обычными бомбами.

### 3.5. Разрушаемые блоки

Блоки могут скрывать:
- Усиление.
- Выход.
- Дополнительную награду.
- В современной кампании — секретный механизм или пасхалку.

Не каждый блок должен содержать предмет.

Разрушение блока сопровождается анимацией, звуком и корректным обновлением логической сетки.

### 3.6. Скрытый выход

В режиме «Классика» выход располагается под разрушаемым блоком.

После уничтожения блока выход становится видимым.

Если враги ещё живы, войти в него нельзя.

Предусмотри исторический вариант наказания за попадание взрывом по открытому выходу: появление дополнительных врагов.

Точное число и разновидности врагов должны задаваться параметрами конкретного пресета или уровня.

В современной кампании допускается альтернативная реакция выхода, но её нужно явно обозначать.

### 3.7. Таймер

Каждый классический уровень имеет ограничение времени.

Исторический режим должен поддерживать пресет, основанный на оригинальных правилах NES, включая начальный лимит 200 игровых секунд.

Учитывай, что темп оригинального игрового таймера не обязательно соответствует обычным реальным секундам.

Для современной кампании допускаются уровни с отдельным настраиваемым лимитом времени.

Если время заканчивается:
- Наступает предусмотренная режимом штрафная фаза.
- В историческом пресете появляются особо опасные противники.
- Игрок получает ясное предупреждение.
- Условия завершения остаются определёнными правилами режима.

Не допускать внезапной гибели без объяснимой причины.

### 3.8. Классические усиления

Обязательные механики:

**Bomb Up:** увеличивает количество одновременно устанавливаемых бомб.

**Fire Up:** увеличивает радиус взрыва.

**Speed Up:** увеличивает скорость движения.

**Remote Detonator:** позволяет взрывать установленные бомбы по команде.

**Wall Pass:** позволяет проходить через определённые разрушаемые блоки.

**Bomb Pass:** позволяет проходить через установленные бомбы.

**Flame Pass:** предоставляет защиту от огня в пределах правил конкретного режима.

**Temporary Invulnerability:** временная неуязвимость.

Для каждого усиления реализовать:
- Условия получения.
- Эффект.
- Предельные значения.
- Взаимодействие с другими усилениями.
- Поведение после потери жизни.
- Сохранение или сброс при переходе между уровнями.
- Визуальный индикатор.
- Автоматические тесты.

В историческом режиме соблюдать выбранные правила утраты улучшений после смерти.

В современной кампании разрешается собственная более мягкая модель потери прогресса.

### 3.9. Противники

Создай оригинальных противников с классическими архетипами поведения:

- Медленный патрульный.
- Быстрый патрульный.
- Преследователь.
- Уклоняющийся от взрывов.
- Проходящий через определённые препятствия.
- Устойчивый к специальным воздействиям.
- Элитный противник.
- Особо опасный противник штрафной фазы.

Все модели, анимации и названия должны быть оригинальными.

### 3.10. Классические бонусные раунды

Предусмотри дополнительный короткий раунд после каждых пяти классических уровней.

Цель:
- Уничтожить максимальное число появляющихся противников.
- Набрать очки за ограниченное время.

В классическом бонусном пресете персонаж защищён от обычных взрывов.

Результат влияет на счёт, но не должен блокировать прохождение кампании.

### 3.11. Система очков

Начислять очки за:
- Уничтожение противников.
- Цепные реакции.
- Бонусные раунды.
- Особые действия.
- Секретные находки.
- Быстрое прохождение, если режим это предусматривает.

Счёт вести отдельно от прогресса уровней.

Не допускать двойного начисления за одну цель.

# ЧАСТЬ III. БОЛЬШИЕ УРОВНИ И ИССЛЕДОВАНИЕ

## 4. Большие карты — обязательное требование

**В BLASTORIA основные уровни не должны умещаться целиком на одном экране.**

Это принципиальное отличие от маленьких арен.

Игрок должен проходить по большим лабиринтам, исследовать новые территории и постепенно открывать карту.

### 4.1. Предлагаемые размеры

Использовать несколько классов карт:

| Тип | Размер логической сетки |
|---|---|
| Тестовая карта | 15 × 11 |
| Малая арена | 21 × 15 |
| Стандартный уровень кампании | 41 × 31 |
| Большой уровень | 61 × 41 |
| Особый уровень | 81 × 61 |
| Крупная карта босса или финала | Индивидуально |

Размеры ориентировочные и должны быть проверены на производительность и качество игрового дизайна.

Тестовая карта 15 × 11 применяется только для разработки и небольших арен.

Она не должна определять основной масштаб одиночной кампании.

### 4.2. Камера

Камера:
- Изометрически-подобная 2.5D.
- Фиксированный основной угол.
- Плавно следует за персонажем.
- Показывает ограниченную часть уровня.
- Не выходит за допустимые границы.
- Поддерживает разные разрешения.
- Не препятствует точному определению клеток.

Предусмотри небольшое опережение камеры по направлению движения, если это улучшает обзор.

Не используй резкие движения камеры.

### 4.3. Видимая область

Игрок должен видеть достаточно пространства, чтобы предсказывать ближайшие взрывы.

Вне экрана продолжаются:
- Работа бомб.
- Движение противников.
- Таймеры.
- Состояние интерактивных объектов.
- События уровня.

Но далёкие визуальные эффекты можно оптимизировать.

Игровая логика не должна останавливаться просто потому, что объект не виден камерой.

### 4.4. Мини-карта

Реализовать мини-карту:

- Открытые исследованные области.
- Положение игрока.
- Ориентиры.
- Обнаруженные выходы.
- Специальные объекты.
- Важные сюжетные цели.

Не раскрывать автоматически неизвестные секретные комнаты и пасхалки.

Предусмотри переключение между небольшой мини-картой и полноэкранной картой исследованной территории.

### 4.5. Структура больших уровней

Большие уровни должны состоять из взаимосвязанных областей:

- Стартовая зона.
- Основные коридоры.
- Разрушаемые перегородки.
- Пространства с противниками.
- Дополнительные маршруты.
- Скрытые комнаты.
- Опциональные опасные участки.
- Секретные зоны.
- Область выхода.

Не создавай огромные пустые пространства ради размера.

Каждая область должна иметь интересную игровую функцию.

### 4.6. Возврат назад

Игрок может возвращаться в ранее исследованные области.

Проверяй:
- Не блокируется ли единственный проход.
- Возможно ли возвращение к выходу.
- Не остаётся ли герой навсегда в изолированной комнате.
- Не закрывает ли случайная генерация обязательные маршруты.

Все обязательные цели должны быть достижимы.

### 4.7. Случайная генерация

Предусмотри seed-based генератор.

Каждая карта должна:
- Иметь воспроизводимый seed.
- Быть проходимой.
- Содержать безопасную стартовую область.
- Иметь корректные позиции противников.
- Не блокировать обязательные цели.
- Учитывать особенности текущего игрового режима.
- Поддерживать уникальные секретные условия.

Не полагайся исключительно на полностью случайные карты.

Используй комбинацию:
- Ручного дизайна.
- Шаблонов.
- Процедурных вариаций.
- Проверки достижимости.

### 4.8. Масштабирование сложности

Для больших карт увеличивай не только количество врагов.

Используй:
- Новые типы противников.
- Сложные маршруты.
- Различные препятствия.
- Комбинации опасностей.
- Дополнительные цели.
- Секреты.
- Ограничение доступных ресурсов.
- Необычные варианты использования бомб.

Не заставляй игрока бесцельно разрушать сотни одинаковых ящиков.

# ЧАСТЬ IV. ДЕСЯТЬ ОРИГИНАЛЬНЫХ ПАСХАЛОК

## 5. Система редких секретов BLASTORIA

В оригинальных аркадах существовали редкие секретные предметы за необычные действия.

В BLASTORIA необходимо создать собственную расширенную систему скрытых артефактов.

Требования:

- Ровно 10 разных видов редких пасхалок на первом этапе.
- Каждая имеет уникальное название.
- У каждой собственная визуальная модель.
- Каждая открывается специальной последовательностью действий.
- Условия не отображаются игроку напрямую.
- Находки фиксируются в секретной коллекции.
- Секрет может давать очки, косметику, дополнительный игровой эффект или открывать особое испытание.
- Пасхалки крайне трудно найти без исследования.
- Дополнительные секреты не требуются для завершения основной кампании.
- Генератор должен гарантировать выполнимость условий.
- Все условия, счётчики и награды хранятся в ресурсах конфигурации.

Не копировать секретные предметы, изображения, названия и точные условия из оригинальной Bomberman.

## Пасхалка № 1. «Призрачный компас»

**Редкость:** Легендарная.

**Секретное условие:**
- На подходящем большом уровне открыть не менее 90% исследуемой карты.
- Не получить урон.
- Не использовать мини-карту.
- Найти три скрытых ориентира, расположенных в разных секторах.
- Завершить уровень, сохранив установленный порядок посещения ориентиров.

**Появление:** В ранее пустовавшей нише стартового сектора появляется светящийся компас.

**Награда:**
- 50 000 очков.
- Постоянный коллекционный артефакт.
- Косметический эффект направления на экране результатов.

Компас не должен автоматически раскрывать секреты в соревновательной игре.

## Пасхалка № 2. «Сердце цепной реакции»

**Редкость:** Легендарная.

**Условие:**
- На специальном уровне запустить одну непрерывную цепочку из не менее 12 разных бомб.
- Самостоятельно поставить стартовую бомбу.
- Последним взрывом разрушить заранее существовавшую запечатанную стену.
- Не получить урон от цепочки.

**Появление:** Из разрушенной стены выпадает пульсирующий кристалл.

**Награда:**
- 100 000 очков.
- Уникальный визуальный эффект цепных взрывов.
- Запись рекорда в коллекции.

Создай специальную проверку графа цепных реакций.

## Пасхалка № 3. «Корона невидимого короля»

**Редкость:** Мифическая.

**Условие:**
- Пройти специальную область, не уничтожив ни одного обычного противника.
- Открыть три скрытых механизма.
- Использовать только разрушение препятствий и отвлечение врагов.
- Добраться до тайного трона, оставаясь незамеченным механизмами обнаружения.

**Награда:**
- 150 000 очков.
- Декоративная корона персонажа.
- Секретная запись в энциклопедии мира.

Этот секрет размещать только на уровнях, где предусмотрена возможность обойти врагов.

## Пасхалка № 4. «Часы последней секунды»

**Редкость:** Мифическая.

**Условие:**
- Заранее обнаружить закрытую временную комнату.
- Активировать её механизм.
- Уничтожить последнего обязательного врага при оставшихся 5–7 секундах по игровому таймеру.
- В Аркаде: после победы активировать необязательный временной механизм в отдельной секретной фазе; официальный таймер уже остановлен. Окно 1–3 секунды отсчитывается таймером испытания, а не продолжающимся таймером этапа. В кампании допустим триггер выхода.

**Награда:**
- 200 000 очков.
- Косметический след в форме песочных частиц.
- Особое достижение.

Проверку выполнять по игровому таймеру, а не по FPS.

## Пасхалка № 5. «Пепельный феникс»

**Редкость:** Легендарная.

**Условие:**
- В вулканическом мире последовательно активировать три древние печати огненной цепной реакцией.
- Между активациями не использовать обычные атакующие бомбы.
- Доставить заряд к центральному алтарю.
- Не погибнуть.

**Награда:**
- 125 000 очков.
- Особая анимация возрождения в кампании.
- Коллекционная статуэтка.

Анимация не предоставляет дополнительных преимуществ в PvP.

## Пасхалка № 6. «Зеркало двойника»

**Редкость:** Мифическая.

**Условие:**
- Найти скрытую зеркальную комнату.
- Активировать древний механизм.
- В течение короткого испытания воспроизвести симметричную последовательность из 8 действий относительно зеркального персонажа.
- Завершить испытание без ошибки.

**Награда:**
- 175 000 очков.
- Декоративная голографическая копия героя в главном меню.
- Секретное испытание на точность управления.

Проверять последовательность игровых действий, а не графические координаты модели.

## Пасхалка № 7. «Кристалл абсолютной тишины»

**Редкость:** Мифическая.

**Условие:**
- Найти древний подземный зал.
- Пройти участок с датчиками вибрации.
- Не использовать взрывы внутри участка.
- Активировать четыре механизма в порядке, подсказанном окружением.
- Преодолеть участок без срабатывания сигнализации.

**Награда:**
- 225 000 очков.
- Уникальная спокойная музыкальная композиция для меню, если оригинальный трек создан.
- Коллекционный кристалл.

Не требовать отключения звука на компьютере: условие определяется действиями внутри игры.

## Пасхалка № 8. «Потерянная звезда»

**Редкость:** Легендарная.

**Условие:**
- Найти три незаметных фрагмента звёздного символа в разных частях большого уровня.
- Обнаружить скрытый телепорт.
- Перенести фрагменты в правильном порядке.
- Завершить испытание за одно прохождение без потери жизни.

**Награда:**
- 250 000 очков.
- Секретная звёздная окраска персонажа.
- Запись в коллекции артефактов.

В официальной Аркаде положение фрагментов фиксировано на этапе 18. В пользовательских картах оно может задаваться генератором и сохраняется в экземпляре карты.

## Пасхалка № 9. «Ключ разрушителя»

**Редкость:** Мифическая.

**Условие:**
- На специальной большой карте открыть все четыре запечатанные технические двери.
- Для каждой двери использовать уникальную комбинацию направления взрыва и активации переключателя.
- Не разрушить ни одного охраняемого энергетического ядра.
- Активировать финальный механизм.

**Награда:**
- 300 000 очков.
- Доступ к дополнительному испытанию с нестандартными препятствиями.
- Декоративный ключ в коллекции.

Все защищённые ядра должны быть хорошо различимы визуально.

## Пасхалка № 10. «Око Бластории»

**Редкость:** Уникальная.

**Условие:**
- Найти предыдущие девять разных артефактов.
- Открыть скрытую область в финальном мире.
- Завершить последовательность из трёх испытаний:
  1. Тактическая цепная реакция.
  2. Лабиринт без использования карты.
  3. Финальная головоломка с четырьмя элементальными механизмами.
- Завершить заключительный этап без потери жизни.

**Награда:**
- 1 000 000 очков.
- Особый косметический облик персонажа.
- Секретная сцена, раскрывающая дополнительную часть истории BLASTORIA.
- Достижение высшей редкости.
- Запись в галерее найденных секретов.

Этот предмет должен быть самым сложным секретом первой коммерческой версии.

## 5.1. Важная система честности пасхалок

Не используй простую случайность типа «один шанс на миллион».

Редкость определяется сложностью действий.

Создай `SecretManager` с подсистемами:
- SecretConditions.
- SecretProgress.
- SecretRewards.
- SecretDiscoveryEvents.
- SecretPersistence.
- SecretValidation.

Требования:
- События обрабатываются единожды.
- Прогресс корректно сбрасывается при провале условия.
- Не возникает ложных активаций.
- Переход между уровнями не дублирует награды.
- Результат зависит от правил, а не от частоты кадров.
- Включена защита от невозможных состояний.
- Секретные условия тестируются автоматически.
- Для секретов есть внутренние отладочные сценарии.

В режиме разработки должны существовать тестовые команды, позволяющие воспроизводить необходимые события и проверять выдачу наград.

В финальной сборке отладочные функции должны быть отключены или надёжно недоступны обычному пользователю.

## 5.2. Скрытые подсказки

Хотя пасхалки трудные, игрок должен иметь шанс догадаться об условиях.

Используй:
- Узоры на стенах.
- Необычные звуки.
- Символы.
- Фрагменты надписей.
- Древние карты.
- Различия в освещении.
- Повторяющиеся элементы архитектуры.
- Секретные наблюдения в коллекции.

Не публикуй точные условия непосредственно в игровых меню.

После открытия артефакта можно показывать его описание и историю находки.

## 5.3. Обычные бонусы и секреты — разные категории

Обычные усиления:
- Часто встречаются.
- Помогают пройти уровень.
- Видимы после разрушения блока.
- Улучшают игровые параметры.

Пасхалки:
- Крайне редкие.
- Требуют необычных действий.
- Могут скрываться в особых зонах.
- Награждают исследование и мастерство.
- Не обязательны для прохождения.
- Не дают несправедливого преимущества в рейтинговом PvP.

Создай отдельные системы хранения и интерфейса для двух категорий.

# ЧАСТЬ V. ИГРОВЫЕ РЕЖИМЫ

## 6. Режим «Классика»

Обязательный основной режим.

Сохраняет историческую основу:
- Установка обычных бомб.
- Крестообразные взрывы.
- Разрушаемые блоки.
- Скрытые выходы.
- Уничтожение всех противников.
- Таймер.
- Классические усиления.
- Система очков.
- Постепенное усложнение.
- Бонусные раунды.

Предусмотри отдельную классическую серию из 50 последовательных уровней, вдохновлённую структурой NES, но с оригинальным дизайном.

Не копируй точные уровни, врагов, оформление или сюжет оригинала.

Для аутентичного пресета допускаются компактные карты. Но современная основная кампания должна состоять из больших многоэкранных карт.

## 7. Режим «Приключение»

Полноценная кампания с большими уровнями.

Целевой объём:
- Четыре мира.
- По десять основных уровней в каждом.
- Четыре босса.
- Дополнительные секретные испытания.
- Сохранение прогресса.
- Исследование территорий.
- Достижения.
- Система коллекционных артефактов.

Классическая механика бомб остаётся базовым способом уничтожения врагов и открытия путей.

## 8. Режим «Аркада»

Действуют полные правила 2.3 ниже: 100 авторских этапов, 10 тем, победа после уничтожения обязательных врагов без выхода; фиксированные секреты, отдельные официальные рекорды. Генерация применяется только в Мастерской.

## 9. Режим «Арена»

Локальные сражения для двух-четырёх игроков в первоначальной версии.

Режимы:
- Каждый сам за себя.
- Командный бой.
- Последний выживший.
- Бой на время.
- Серия раундов.

Арены могут быть компактными, но должны поддерживать вариативность.

Нужны:
- Выбор персонажа.
- Выбор карты.
- Настройка числа раундов.
- Настройка бонусов.
- Управление с геймпада.
- Подведение итогов.
- Реванш.

## 10. Режим «Кооператив»

Планируемое совместное прохождение больших уровней.

Предусмотри:
- Общую цель.
- Совместные механики.
- Поддержку разных устройств ввода.
- Дружественный огонь как настраиваемую опцию.
- Корректную работу камеры.

Для больших уровней заранее исследуй, будет ли удобнее общая камера, динамический split-screen или альтернативный вариант.

Не внедряй split-screen без тестирования производительности и удобства.

## 11. Будущие дополнительные режимы

После стабилизации основного игрового процесса:

- Охота за сокровищами.
- Бесконечное выживание.
- Испытания с боссами.
- Ежедневная карта.
- Редактор арен.
- Steam Workshop, если интеграция будет реализована.
- Онлайн-лобби.
- Сетевые сражения.
- Кооператив по сети.

Новые режимы должны повторно использовать базовые системы игры, а не создавать независимые реализации механики бомб.

# ЧАСТЬ VI. ГРАФИКА И ХУДОЖЕСТВЕННАЯ КОНЦЕПЦИЯ

## 12. Современная графика 2.5D

Зафиксировать графическое направление без возможности незаметно изменить его на обычную плоскую 2D-графику.

Основные требования:

- Настоящие трёхмерные игровые объекты.
- Трёхмерные персонажи.
- Фиксированная камера сверху под углом.
- Стилизованная качественная графика.
- Мягкое художественное освещение.
- Тени.
- Выразительные материалы.
- Плавные анимации.
- Частицы.
- Динамические эффекты взрывов.
- Реакция объектов на разрушения.
- Красивые переходы.
- Умеренные постэффекты.
- Поддержка настроек качества.

Визуальный ориентир — современная премиальная инди-игра с мультяшной стилизацией и высокой читаемостью.

Не использовать реалистичные человеческие модели или сложную фотореалистичную графику без причины.

Внешний вид должен быть ярким, оригинальным, приятным и узнаваемым.

### 12.1. Вид сверху

Поле должно хорошо просматриваться.

Игрок должен понимать:
- Где находится его персонаж.
- Где стоят бомбы.
- Когда ожидается взрыв.
- Какие клетки опасны.
- Где разрушаемые стены.
- Какие объекты интерактивные.
- Где находится выход.

Персонажи не должны сливаться с окружением.

Декоративные элементы не должны закрывать критически важные клетки.

### 12.2. Персонажи

Создай собственный набор героев.

Разработай:
- Силуэты.
- Варианты голов и костюмов.
- Цветовые схемы.
- Анимацию ожидания.
- Бег.
- Установку бомбы.
- Получение урона.
- Гибель.
- Победу.
- Эмоции.

Не копировать внешний вид героев Bomberman.

### 12.3. Миры

**Мир 1 — Древние джунгли.**
Зелёная и золотистая палитра, руины, заросли, древние механизмы.

**Мир 2 — Ледяная крепость.**
Голубые и фиолетовые оттенки, лёд, кристаллы, замёрзшие конструкции.

**Мир 3 — Вулканические глубины.**
Оранжево-красная палитра, лава, чёрный камень, жар, пепел.

**Мир 4 — Кибергород.**
Неон, технологии, электрические препятствия, лазеры и порталы.

Для каждого мира создать единый набор визуальных стандартов.

### 12.4. Эффекты взрывов

Реализовать:
- Пульсацию бомбы перед детонацией.
- Видимый момент срабатывания.
- Направленный огненный взрыв.
- Реакцию освещения.
- Частицы.
- Разлетающиеся элементы препятствий.
- Дым.
- Искры.
- Короткую управляемую тряску камеры.
- Визуальное отображение цепной реакции.

Не допускать расхождения визуального взрыва с логической областью поражения.

### 12.5. Оптимизация

Для слабых компьютеров предусмотри:
- Уменьшение качества теней.
- Ограничение частиц.
- Упрощённые материалы.
- Отключение дорогих эффектов.
- Масштабирование рендеринга.
- Настройки разрешения.
- Ограничение FPS.

Разработай три профиля качества: Low, Medium, High.

- Сложные цепные реакции.

### Карта 10. «Сердце Бластории»
Уровни 91–100.

Особенности:
- Комбинации элементов предыдущих карт.
- Сложные лабиринты.
- Элитные противники.
- Несколько типов активных ловушек.
- Особые испытания.
- Финальная последовательность из десяти сложных уровней.

## 3. Увеличение сложности

Разработать отдельный `ArcadeProgressionManager`.

Сложность должна зависеть от:
- Номера уровня.
- Типа карты.
- Числа обязательных противников.
- Типов противников.
- Скорости движения врагов.
- Их способности избегать взрывов.
- Плотности лабиринта.
- Количества опасных механизмов.
- Доступности бонусов.
- Лимита времени.
- Особых правил уровня.

Каждые десять уровней вводить новую группу механик.

Не допускать резких необоснованных скачков сложности.

Первые уровни должны быть понятны новичкам.

Последние десять должны стать серьёзным испытанием даже для опытных игроков.

Сложность определяется прежде всего качеством сочетания механик, а не искусственным увеличением здоровья врагов.

## 4. Фиксированная структура официальных уровней

Официальная Аркада должна использовать заранее созданные и сохранённые уровни.

Запрещено:
- Заменять авторскую геометрию случайной генерацией.
- Менять расположение секретов при обычном повторном прохождении.
- Создавать непроходимые варианты карт.
- Случайно удалять обязательных врагов.
- Перемещать пасхалки на неподходящие уровни.

Разрешено:
- Повторять уровни.
- Сохранять лучшие результаты.
- Выбирать уже открытые уровни.
- Использовать заранее проверенные варианты сложности, если они отделены от основного рейтинга.

Официальные рекорды должны сравниваться при одинаковых правилах.

# ЧАСТЬ II. ФИКСИРОВАННЫЕ ПАСХАЛКИ

## 5. Распределение десяти секретов

Использовать утверждённые ранее десять оригинальных артефактов.

Для первого выпуска зафиксировать следующее распределение:

| Пасхалка | Официальная карта | Уровень |
|---|---|---|
| Призрачный компас | Зелёный лабиринт | 9 |
| Потерянная звезда | Затопленные руины | 18 |
| Корона невидимого короля | Песчаная цитадель | 29 |
| Пепельный феникс | Огненные шахты | 37 |
| Часы последней секунды | Ледяной дворец | 49 |
| Сердце цепной реакции | Механический завод | 58 |
| Кристалл абсолютной тишины | Призрачные катакомбы | 67 |
| Ключ разрушителя | Электрический город | 79 |
| Зеркало двойника | Кристальный лабиринт | 87 |
| Око Бластории | Сердце Бластории | 100 |

Это первоначальное фиксированное распределение.

Если условия конкретной пасхалки из предыдущей спецификации противоречат тематике карты, адаптировать окружение и специальные испытания, сохраняя уникальную механику артефакта.

Например, «Часы последней секунды» требуют специальной временной комнаты и предусмотренного выхода. Поскольку в Аркаде обязательного выхода нет, финальный триггер адаптировать: уничтожить последнего врага в заданном временном окне и активировать необязательный временной механизм. Активация не должна быть необходима для обычной победы.

Для «Короны невидимого короля» скрытое испытание не должно отменять необходимость уничтожения всех обязательных врагов для основного прохождения. Условие прохождения без убийств относится только к отдельной секретной зоне.

Для «Ока Бластории» предусмотреть проверку наличия предыдущих девяти артефактов в коллекции игрока.

## 6. Где хранить размещение пасхалок

Создать:
- `ArcadeSecretRegistry`.
- `SecretConditionValidator`.
- `SecretRewardManager`.
- `SecretCollection`.

Зафиксировать:
- ID секретного предмета.
- ID официальной карты.
- Номер уровня.
- Координаты или специальную зону.
- Условия активации.
- Правила награды.
- Состояние получения.

Размещение и условия не должны зависеть от случайного seed официального режима.

У каждого секрета должна быть внутренняя проверка достижимости.

Секреты должны оставаться очень трудными, но честными.

Не раскрывать условия игроку напрямую.

Использовать косвенные подсказки в окружении.

# ЧАСТЬ III. НОВЫЙ РЕЖИМ «МАСТЕРСКАЯ КАРТ»

## 7. Назначение редактора

Добавить отдельный пункт главного меню:

**Мастерская карт**

Это полноценный пользовательский режим для создания, настройки, генерации, сохранения и обмена картами.

Игрок должен иметь возможность без программирования самостоятельно создать собственный игровой уровень.

### Главное отличие

В официальной Аркаде карты фиксированы.

В Мастерской игрок задаёт набор элементов и правила, после чего генератор создаёт карту случайным образом на основании выбранной конфигурации.

При каждой новой генерации формируется новый вариант.

При этом сохранённый экземпляр карты должен оставаться неизменным до тех пор, пока пользователь сам не решит его изменить или сгенерировать заново.

## 8. Возможности редактора

В редакторе должны быть доступны все игровые категории объектов, которые поддерживает текущая версия игры.

### 8.1. Геометрия

Игрок может добавлять:
- Неразрушимые стены.
- Разрушаемые блоки.
- Свободные клетки.
- Проходы.
- Двери.
- Мосты.
- Платформы.
- Границы уровня.
- Декоративные объекты.

### 8.2. Окружение

Доступны:
- Лёд.
- Вода.
- Лава.
- Конвейеры.
- Телепорты.
- Лазеры.
- Электрические зоны.
- Движущиеся препятствия.
- Опасные поверхности.
- Переключатели.
- Специальные механизмы.

### 8.3. Противники

Игрок выбирает:
- Типы врагов.
- Количество.
- Диапазон сложности.
- Скорость.
- Поведение ИИ.
- Обязательность уничтожения.
- Разрешённые области появления.
- Допустимые типы элитных противников.

### 8.4. Бомбы

Настраиваются:
- Разрешённые типы.
- Количество.
- Начальная дальность.
- Таймер.
- Возможность дистанционной активации.
- Особые эффекты.
- Ограничения.

### 8.5. Бонусы

Можно:
- Добавлять доступные усиления.
- Исключать ненужные.
- Устанавливать количество.
- Настраивать допустимую частоту появления.
- Прятать под разрушаемыми блоками.
- Ограничивать усиления правилами режима.

### 8.6. Пасхалки

Редактор должен позволять использовать все десять оригинальных секретных предметов.

Игрок может:
- Включить секретные механики.
- Выбрать конкретный артефакт.
- Разместить подходящую секретную зону.
- Определить допустимые места появления.
- Настроить условия доступных пользовательских испытаний.

Пользовательские карты не должны выдавать официальные редкие достижения или официальные рейтинговые награды автоматически.

В коллекции разделять:
- Официальные открытия.
- Находки в пользовательских картах.

Это предотвращает обесценивание редких секретов официальной Аркады.

### 8.7. Игроки

Настраивать:
- Число игроков.
- Начальные позиции.
- Команды.
- Доступное управление.
- Режим сражения.
- Дополнительные правила возрождения, если они предусмотрены выбранным режимом.

### 8.8. Параметры уровня

Игрок может выбирать:
- Размер карты.
- Тему окружения.
- Сложность.
- Время.
- Число врагов.
- Набор бонусов.
- Разрушаемость препятствий.
- Количество опасных зон.
- Плотность блоков.
- Наличие тайников.
- Режим победы.
- Игровой режим.
- Дополнительные ограничения.

В интерфейсе показывать допустимые пределы параметров и предупреждать о несовместимых настройках.

# ЧАСТЬ IV. ПРОЦЕДУРНЫЙ ГЕНЕРАТОР МАСТЕРСКОЙ

## 9. Принцип генерации

Создать `CustomMapGenerator`.

Генератор должен собирать новую карту из элементов, выбранных пользователем.

Алгоритм:

1. Получить настройки пользователя.
2. Проверить совместимость объектов и правил.
3. Определить размер карты.
4. Построить базовую структуру лабиринта.
5. Разместить неразрушимые стены.
6. Разместить разрушаемые блоки.
7. Построить обязательные маршруты.
8. Назначить стартовые позиции.
9. Разместить противников.
10. Разместить выбранные ловушки.
11. Разместить бонусы.
12. Разместить разрешённые секреты.
13. Проверить достижимость.
14. Проверить условия победы.
15. Проверить отсутствие невозможных ситуаций.
16. Сформировать готовую карту.
17. Показать предпросмотр.
18. Разрешить начать игру или сохранить результат.

### 9.1. Генерация новой карты каждый раз

Каждое нажатие «Сгенерировать» по умолчанию использует новый seed.

Это создаёт новый вариант расположения разрешённых объектов.

Карта должна сохранять выбранные пользователем параметры.

Если пользователь указал:
- Только огненных врагов.
- Без воды.
- С тремя бонусами.
- С пятью телепортами.

Генератор должен соблюдать эти настройки.

Если создать карту с такими параметрами невозможно, показать объяснение и предложить конкретное исправление.

Не подменять пользовательские требования произвольными объектами.

### 9.2. Повторяемость

Несмотря на случайную генерацию, пользователь должен иметь возможность повторно открыть ту же карту.

Поэтому сохранять:
- Seed.
- Версию алгоритма генерации.
- Правила.
- Настройки.
- Итоговое расположение объектов.

Для точного повторного прохождения сохранять готовый экземпляр карты, а не только seed.

Повторная генерация из шаблона создаёт новую карту.

Повторное прохождение сохранённой карты сохраняет её исходную геометрию и содержимое.

### 9.3. Проверка проходимости

Генератор обязан проверять:
- Стартовую область.
- Наличие достижимых врагов.
- Доступность обязательных целей.
- Возможность использовать доступные бомбы.
- Отсутствие изолированных обязательных врагов.
- Возможность покинуть опасные области.
- Возможность завершить матч.
- Корректные условия победы.
- Отсутствие непрерывных критических ошибок.

Для сложных пользовательских механик предусмотреть расширенную проверку достижимости.

Если автоматическая проверка не может гарантировать решаемость карты, показать предупреждение и пометить карту как непроверенную, а не заявлять, что она гарантированно проходима.

- Проверка безопасности.
- Проверка совместимости.
- Автоматическое создание записи в пользовательской библиотеке.

Формат может быть JSON с расширением `.blastmap` либо иной документированный версионированный формат.

Не включать исполняемые скрипты, произвольный код или небезопасные пути файлов в пользовательские карты.

Проверять размеры, количество объектов, допустимые типы ресурсов и ограничения входных данных.

### 14.1. Отправка другу

Пользователь может:
- Экспортировать файл карты.
- Передать его другому игроку.
- Импортировать полученный файл.
- Сыграть на карте.
- Повторить её.
- Изменить копию, если автор разрешил использование как шаблона.

При наличии локального мультиплеера карта должна загружаться одинаково для всех участников матча.

### 14.2. Steam Workshop

Запланировать интеграцию Steam Workshop как предпочтительный способ публикации пользовательских карт в сообществе Steam.

После получения доступа к соответствующим инструментам и реализации интеграции предусмотреть:
- Публикацию карты.
- Название и описание.
- Скриншот-превью.
- Загрузку карт других игроков.
- Подписку.
- Обновление опубликованной карты.
- Удаление или снятие с публикации собственной карты.
- Проверку совместимости версий.
- Обработку ошибок загрузки.
- Соблюдение правил Steam.

Не объявлять Workshop реализованным до проверки интеграции.

### 14.3. Будущая совместимость с консолями

Поскольку Xbox, PlayStation и другие устройства запланированы на будущее, отделить пользовательские карты от Steam-специфического способа распространения.

Создать платформенно независимый `MapSharingService`.

Возможные адаптеры:
- LocalFileSharing.
- SteamWorkshopSharing.
- FuturePlatformSharing.

Не делать Steam Workshop единственным способом хранения или обмена пользовательскими картами.

### 2.2. Правила ранжирования

Основной рейтинг Аркады — максимальное число очков.

Если очки совпадают:
1. Выше игрок с меньшим временем.
2. При равенстве — с меньшим числом потерянных жизней.
3. При полном равенстве использовать заранее определённое стабильное правило, например время подтверждения результата.

Отдельный скоростной рейтинг — минимальное время.

Для него требуется успешное завершение уровня.

Не смешивать результаты:
- Разных версий правил.
- Различных режимов.
- Несопоставимых настроек сложности.
- Пользовательских и официальных карт.

- Переключение «Очки / Время».

- Просмотр лучшего результата.
- Пагинация.
- Корректная загрузка и обработка ошибок подключения.

Использовать Steam Leaderboards.

Учесть, что Steam Leaderboards поддерживает числовой результат и ограниченный набор дополнительных числовых данных.

- Контроль последовательности.

- При необходимости — запись и проверку воспроизводимого игрового replay.

Не раскрывать количество ожидающих открытий.

Когда игрок впервые находит артефакт:
- Показывается короткая красивая анимация.
- Отображается его название.
- Добавляется 3D-модель в личную коллекцию.
- Записывается дата находки.
- Указывается режим.
- Указывается уровень или карта.
- Сохраняется описание открытия.
- Начисляется предусмотренная награда.
- Запускается предусмотренное достижение, если оно связано с находкой.

Коллекция содержит только реально найденные данным игроком предметы.

Игрок вправе повторно рассматривать уже открытые артефакты.

Ранее не найденные предметы не отображаются.

Не показывать технические ID, индексы или внутренние номера секретов.

# ЧАСТЬ III. ГЛОБАЛЬНЫЙ ЗАЛ ПЕРВООТКРЫВАТЕЛЕЙ

## 5. Главная механика мирового первенства

Создать экран:

**«Зал первооткрывателей»**

Это отдельная глобальная таблица.

Её основная задача — навсегда фиксировать игрока, который первым в мире подтвердил открытие конкретной пасхалки BLASTORIA.

### Главное правило

**У каждой пасхалки может быть только один официальный первооткрыватель.**

В таблице отображается только этот первый игрок.

Остальные игроки, нашедшие тот же предмет позднее, не добавляются в глобальный зал для этой пасхалки.

При этом каждый из них получает предмет в личную коллекцию.

### 5.1. До обнаружения

Если пасхалку не нашёл ни один игрок:

- Она отсутствует в глобальной таблице.
- Её название не отображается.
- Её описание не показывается.
- Её изображение не отображается.
- Нет пустой строки для будущего предмета.
- Нет счётчика общего количества.

Если ни одна пасхалка ещё не открыта, таблица показывает сообщение:

«Мир BLASTORIA ещё хранит свои тайны. Первые открытия впереди».

### 5.2. После первого обнаружения

В момент первого подтверждённого глобального открытия автоматически создаётся строка.

Пример структуры:

| Артефакт | Первооткрыватель | Дата открытия | Уровень |
|---|---|---|---|

Система отображает:
- Название артефакта.
- Оригинальную иконку.
- Публичное имя игрока Steam.
- Дату и время подтверждения.
- Режим или уровень открытия.
- Почётную отметку «Первый первооткрыватель».

Показывать только реально открытые артефакты.

Количество строк растёт по мере открытий.

### 5.3. Если пасхалку находят два игрока одновременно

Реализовать атомарную серверную операцию.

Сервер должен:
1. Получить подтверждённые заявки.
2. Проверить подлинность игроков.
3. Проверить игровые условия.
4. Попытаться создать запись первого обнаружения.
5. Разрешить создание ровно одной записи для конкретного артефакта.
6. Вернуть победителя операции.
7. Для остальных игроков сохранить обычное обнаружение без статуса первооткрывателя.

В базе данных установить уникальное ограничение по идентификатору секретного артефакта в глобальном реестре первооткрывателей.

Не выбирать победителя по времени на компьютере игрока.

Источником определения первенства должен быть сервер.

### 5.4. Момент первого открытия

Принимать за официальное первое обнаружение момент успешной серверной фиксации проверенной заявки.

Офлайн-находка сохраняется локально и синхронизируется после подключения.

Но офлайн-находка сама по себе не резервирует мировой статус первого открытия задним числом.

Это правило должно быть заранее известно игрокам, чтобы не возникало споров.

### 5.5. Постоянство признания

После фиксации первооткрыватель сохраняет свой статус.

Повторное получение артефакта другим игроком не изменяет запись.

Если позже выявлено мошенничество или техническая ошибка, предусмотреть отдельную защищённую административную процедуру пересмотра с журналированием основания и решения.

Не позволять обычному игровому клиенту удалять или изменять глобальное первенство.

### 5.6. Оповещение об открытии

После первого мирового обнаружения:
- В глобальном зале появляется запись.
- Первооткрыватель получает уникальную поздравительную анимацию.
- В личной коллекции появляется почётная отметка.
- Остальные игроки видят новую запись при обновлении глобального зала.

Опционально добавить внутриигровое новостное сообщение:

«В BLASTORIA раскрыта новая тайна!»

Не раскрывать местоположение или условия ещё не найденных секретов.

### 5.7. Персональные данные

Использовать публичное имя Steam с учётом актуальных требований платформы.

Для внутренней идентификации использовать SteamID либо другой допустимый проверенный идентификатор.

Предусмотреть изменение отображаемого имени.

Не показывать адреса электронной почты, IP-адреса или непубличные сведения.

# ЧАСТЬ IV. СЕРВЕРНЫЙ РЕЕСТР СЕКРЕТОВ

## 6. Архитектура

Steam Achievements и Steam Leaderboards не заменяют защищённый реестр первых открытий.

Создать самостоятельный серверный компонент:

`DiscoveryRegistryService`

Основные компоненты:

    SecretDiscoveryClient
    DiscoveryVerificationService
    DiscoveryRegistryService
    FirstDiscoveryResolver
    PlayerSecretCollection
    PublicDiscoveryFeed
    DiscoveryAuditLog

### 6.1. Основные данные

Для каждой пасхалки хранить:
- Внутренний ID.
- Версию условий.
- ID официальной карты.
- ID уровня.
- Статус доступности.
- Проверяемую запись первого открытия.
- Идентификатор первооткрывателя.
- Серверное время подтверждения.
- Подтверждение валидности игровой попытки.

Не отправлять клиенту общий список ещё не открытых пасхалок через публичные API.

Клиент получает:
- Собственные подтверждённые открытия.
- Глобальный список уже публично обнаруженных артефактов.

### 6.2. Проверка подлинности

Использовать корректную авторизацию через Steam, когда она реализована и доступна.

Не доверять переданному клиентом произвольному SteamID без проверки.

Не хранить секретные серверные ключи в Godot-клиенте.

Не принимать простое сообщение `secret_found=true` как достаточное доказательство.

Для проверки предусмотреть:
- Идентификатор попытки.
- Версию уровня.
- Допустимые события.
- Проверку условий.
- Однократность заявки.
- Срок действия.
- Журнал проверки.

Для наиболее ценных открытий использовать серверно подтверждённую симуляцию или проверяемую запись прохождения.

Учитывать, что клиентский replay сам по себе не является абсолютным доказательством честности, если игрок контролирует все входные данные.

### 6.3. Минимальная серверная инфраструктура

Использовать защищённое API и базу данных.

Не создавать чрезмерно дорогую инфраструктуру.

Подготовить вариант реализации:
- Лёгкий API-сервис.
- Реляционная БД.
- Атомарные транзакции.
- Ограничения уникальности.
- Журнал подтверждений.
- Резервное копирование.
- Мониторинг ошибок.
- Защита запросов от злоупотреблений.

Реализацию адаптировать к доступному хостингу и фактическим требованиям нагрузки.

Не считать существование сервера обязательным для запуска одиночной игры.

При недоступности сервера обычная Кампания и Аркада должны продолжать работать локально.

# ЧАСТЬ V. STEAM ACHIEVEMENTS

## 7. Общая система

Создать `AchievementManager`.

Интегрировать его с:
- Кампанией.
- Аркадой.
- Мультиплеером.
- Мастерской карт.
- Секретами.
- Системой рекордов.

Достижения должны работать как события, подтверждаемые игровой логикой.

Не привязывать выдачу достижения к нажатию кнопки интерфейса.

В Steam использовать официальную систему Stats & Achievements и поддерживаемое решение интеграции Steamworks с Godot.

### 7.1. Основные требования

Каждое достижение:
- Имеет постоянный API ID.
- Имеет название.
- Имеет описание.
- Имеет собственную иконку.
- Поддерживает русский и английский языки.
- Выдаётся однократно.
- Не выдаётся в отладочном режиме.
- Не зависит от FPS.
- Сохраняется при допустимых сбоях синхронизации.

Не изменять API ID опубликованных достижений без необходимости.

Не создавать достижений, которые невозможно получить из-за отсутствующего контента.

    AchievementRegistry
    AchievementEventRouter

    SteamAchievementAdapter
    AchievementSyncQueue

Для локальных достижений использовать накопление событий и надёжное сохранение.

- Отправлять новые события.
- Сохранять изменения через поддерживаемый API.

### 15.1. Особое правило глобального первенства

Достижение `ACH_SECRET_DISCOVERER` можно выдавать только после получения серверного подтверждения официального первенства.

Не выдавать его по локальной записи.

Нельзя разблокировать его только изменением файла сохранения.

Поскольку Steam Achievements сами по себе не обеспечивают стопроцентной защиты от внешних манипуляций клиентом, защищённым источником статуса первооткрывателя остаётся серверный реестр.

# ЧАСТЬ X. ТЕСТИРОВАНИЕ

## 17. Тесты рекордов

Обязательно проверить:
1. Результат сохраняется.
2. Лучшее время обновляется корректно.
3. Более плохой результат не заменяет лучший.
4. При одинаковом числе очков правильно применяется правило сравнения.
5. Таблицы разных уровней независимы.
6. Рекорды друзей фильтруются корректно.
7. Пользовательские карты не влияют на официальные рекорды.

11. Изменение имени Steam не теряет идентичность первооткрывателя.
12. Публичный API не сообщает о неоткрытых секретах.
13. Коллекция синхронизируется корректно.
14. Достижение первого в мире выдаётся только подтверждённому первооткрывателю.

## 19. Тесты Steam Achievements
